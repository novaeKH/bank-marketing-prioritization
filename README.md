# Приоритизация клиентов для банковского обзвона

Бинарная классификация для ситуации, в которой банк не может связаться со всеми
клиентами и должен заранее выбрать наиболее перспективные контакты. Модель
формирует ранжированный список, а качество решения оценивается при фиксированном
бюджете — `10%` клиентской базы.

## Ключевой результат

На финальном временном периоде Logistic Regression получила:

| Метрика | Значение |
|---|---:|
| Average Precision | **0.530** |
| ROC-AUC | **0.745** |
| Precision@10% | **58.7%** |
| Recall@10% | **19.1%** |
| Lift@10% | **1.91** |

При бюджете в 824 звонка модель нашла 484 положительных ответа. Случайный выбор
дал бы около 254, поэтому приоритизация почти вдвое увеличивает концентрацию
целевых клиентов.

## Данные

Использован полный набор
[UCI Bank Marketing](https://archive.ics.uci.edu/dataset/222/bank+marketing):
41 188 наблюдений, упорядоченных по времени с мая 2008 по ноябрь 2010 года.
Целевая переменная `y` показывает, оформил ли клиент срочный депозит.

Признак `duration` исключён: длительность разговора становится известна только
после звонка и создаёт утечку данных для модели, которая должна работать до
контакта с клиентом.

## Валидация

- последние 20% наблюдений оставлены как финальный будущий период;
- модели сравниваются на временных фолдах внутри оставшихся 80%;
- случайное разбиение не используется, чтобы не смешивать разные кампании;
- модель выбирается не только по ROC-AUC, но и по метрикам ранжирования при
  рабочем бюджете `Top 10%`.

Такое разбиение выявило заметный сдвиг доли положительных ответов между
кампаниями. Более простая Logistic Regression оказалась устойчивее дерева и
Random Forest на временных фолдах и поэтому выбрана финальной моделью.

cd bank-marketing-prioritization

```bash
pip install -r requirements.txt

```

Notebook уже содержит выполненные ячейки и итоговые таблицы. При повторном
запуске он обучает модели, рассчитывает временную валидацию и пересоздаёт
артефакты в `models/` и `outputs/`.

## Ограничения

- данные относятся к кампаниям 2008–2010 годов, поэтому абсолютные показатели
  нельзя переносить на современные кампании без повторной проверки;
- в данных нет идентификатора клиента, и невозможно проверить повторные контакты
  одного человека между периодами;
- отсутствуют стоимость звонка и прибыль от депозита, поэтому проект оценивает
  качество приоритизации, а не денежный эффект;
- перед внедрением потребуются мониторинг drift и регулярная перекалибровка.
